# S6 — Confirmed combat feedback and compact HUD

## Status and run

Implementation ready for owner milestone playtest. On November 5, 2026 the owner accepted S5 (“i like it”) and authorized the next milestone. This pass makes combat outcomes easier to read while preserving the accepted solo deathmatch, artwork, weapon tuning and vector drift.

Run `npm run dev`, then open http://127.0.0.1:5173/. The compact HUD shows HP/protection or respawn, cannon state, smoke cooldown and quiet/firing-reveal facts. Health and charge meters sit below it; current control bindings are along the bottom. Full charge explicitly says RELEASE and counts down time to vent. Range and guided training remain available.

## Feedback and information boundaries

A player gets HIT CONFIRMED only when their shell damages a tank that their team can see at impact. A visible lethal outcome involving their shell adds ENEMY DESTROYED. If two allied shells contribute to a same-tick destruction, both contributors can receive the destruction confirmation; this is not individual kill-credit accounting. The existing team kill score remains authoritative. Walls and unseen targets do not grant hit confirmations.

The damaged actor receives an eight-sector incoming trajectory cue. Screen-edge chevrons and text show its coarse direction; this is the direction the shell arrived from, not a hidden shooter's current position or origin. It contains no attacker/target ID, coordinates, distance, exact angle or shell owner. Confirmation and direction can appear together. Both remain visible with muted audio, reduced motion and low effects. Existing authorized world impact/destruction audio remains; no new audio assets are added.

The simulation owns the cues, retains them for one simulation second and caps aggregate storage at 32. Observations contain only the requested allied listener's cues, copied by value. Pause freezes expiry; restart clears cues while preserving monotonic cue IDs. Private shell ownership attributes confirmations, but the projectile DTO still omits ownership. The client does not infer hits from HP changes in arbitrary enemy observations or from generic impact effects.

A new regression exposed an existing destruction-effect leak: destroying a concealed brush occupant could emit an exact-location destruction ring to a team that could see the ground but not the tank. Actor-origin effects now capture recipient authorization at emission/impact; concealed enemy destructions and vents are withheld. Authorized ground-impact effects remain separate. Destruction visibility is captured before all same-tick HP changes so simultaneous deaths do not make effect delivery depend on actor iteration order. This fixes presentation authorization; damage and scoring rules are unchanged.

Protocol/content versions are 6 for the new observation field. Offline asset versions continue to be generated from complete production bundle hashes.

## TDD and validation

Tests preceded behavior. Four initial feedback tests failed because visible personal hits, destruction, incoming direction and expiry were absent. A separate regression failed because a concealed tank's destruction event exposed its position. After the first fix, a lethal-trade regression failed because one observer's earlier death suppressed an otherwise visible destruction; capturing authorization before damage and using that snapshot fixed it. The pure HUD tests initially failed on charge/vent/recovery states and cue expiry. Browser acceptance initially failed because on-screen feedback was absent, then passed after integration.

Local verification:

- 100 unit tests pass, including eight feedback boundary/lifecycle tests and two HUD-state tests.
- All 25 browser tests pass: muted/reduced-effects feedback and expiry, sprite hide/reveal, real Worker replay/combat, actual nine-exercise training, controls/settings, focus safety and production offline restart/repair.
- Strict TypeScript/production build and authored map validation pass.
- 100 normal-preset seeded matches with an idle human all terminated. All were Red wins; deaths 2,128, maximum shells 5, longest live-bot stop 1.77 seconds, total ticks 979,329. These match the S4 normal-preset aggregate and are not difficulty calibration.
- A visual check of the compact HUD during charge/cancel/pause found no page errors.

One [manual GitHub CI checkpoint](https://github.com/revoo/Ironveil/actions/runs/42069144282) was dispatched for source commit a1ae2f2 to validate the accumulated S4–S6 work. It passed. Its successful conclusion was retrieved during solo completion using curl after Python DNS resolution failed. This validates that checkpoint; a separate final source check covers the solo completion slice.
