## Presentation decisions

Original code-generated artwork lives in `client/art.ts`. Static grass tufts, road gravel, mud mottling and top-down foliage use only known map geometry. Foliage is contained in existing brush tiles and drawn below tanks; it adds no canopy occlusion, collision or live evidence. Wall panels follow the existing collision rectangles. No persistent dust, hull trails, wreck cover or dynamic scenery was added. Mud tread stamps remain the only persistent tactical evidence.

The battlefield is baked once into a texture. Tank hull and turret textures are generated once and reused. Hulls have tread/armor detail; turrets rotate independently and retain cosmetic player recoil. The player has a circle, the allied bot a cross and enemy tanks a triangle, in addition to separate palettes. HP bars, spawn-protection rings for other actors, requested aim, charge feedback, fog, smoke, stale sightings and sound cues are retained.

Other actors' sprites exist only for living actors in the authorized observation. Losing a contact destroys its hull/turret sprites; a later reveal creates them at its newly authorized pose. Existing interpolation buffers still clear on contact changes. No hidden simulation state enters the artwork planner or renderer. Rendered sprite counts in the existing developer diagnostics allow browser acceptance to check lifecycle transitions.

Artwork is bundled code, so the existing versioned offline shell covers it without external downloads. Protocol/content versions remain 5: simulation content and the observation contract are unchanged; the offline build hash changes with the art bundle.

## Tests and checks

TDD preceded implementation. Static-art tests initially failed because the dressing plan was empty; they now verify deterministic nonempty dressing, no source-map mutation, foliage inside brush and bounded positions outside wall interiors. The new browser acceptance initially failed because the sprite presentation was absent. After implementation it verifies an enemy sprite is present, removed on hide and recreated on authorized reveal, while the ally remains present. The initial failure is evidence of the missing sprite feature, not a claim that the previous graphics renderer leaked hidden actors.

Local results:

- 90 unit tests pass; strict TypeScript/production build and map validation pass.
- All 24 browser tests pass, including sprite lifecycle, real Worker combat, actual nine-exercise training, settings and a full production browser restart offline.
- After the final foliage styling adjustment, the targeted sprite/offline suite passed again (4 tests), and the art tests/build passed again.
- Visual checks covered the battlefield and tanks at normal size, device scale factor 2, movement/firing and resizing from 1280×900 to 1000×800. No page errors occurred. A short headless Chromium sample on the existing M1 Pro reference Mac measured p95 requestAnimationFrame interval of 16.8 ms across 179 intervals. This is a local smoke measurement, not broad hardware/browser performance certification or an effects-heavy soak.

No additional headless match sweep was needed because shared rules were unchanged; S4's 300-match evidence remains recorded separately. No GitHub CI run was triggered. Manual CI remains reserved for a larger accepted checkpoint.

## Remaining evaluation

Owner playtest should judge terrain recognition, tank/barrel readability against brush and mud, team identification, track/shell visibility, and whether the new art distracts from fighting. The map remains the small authored Relay Yard layout; foliage is brush dressing rather than a new forest mechanic. The art is intentionally restrained and may need further visual refinement. Muted/reduced-effects usability, unfamiliar-player teaching success and broad browser/device coverage still need human evidence. Sound remains procedural placeholder audio. The existing large Phaser bundle warning remains. Online work, new mechanics, additional maps and release deployment remain deferred.
