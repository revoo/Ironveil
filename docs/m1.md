# M1 movement playground report

## What works

The local playground advances a tank in the shared simulation inside a Worker. WASD drives in world directions; the hull turns towards the requested direction and the separately drawn turret turns toward the mouse. Shift slows movement for silent running. Grass, road, mud and brush have their specified speed factors, while walls and world bounds block the circular hull. The camera follows with bounded aim lead. The HUD shows speed, terrain and when the silent speed cap has been reached. Losing focus neutralizes movement.

Run `npm ci` and `npm run dev`, then open http://127.0.0.1:5173/ and click the game. Use WASD, mouse and Shift. The server connection remains an M0 diagnostic; the movement playground is local, not an online game.

## Verification

`npm test` covers diagonal input, rotation limits, turning in place, braking, terrain and silent speed, wall sliding, and fixed simulation steps across different render schedules. The browser was checked manually for drawing, Worker startup, server connection and driving input. Playwright checks that focus loss neutralizes a held driving input. `npm run build` and `npm run validate:map` also pass.

## Status and limitations

M1 movement playground is **complete as an initial slice**. The owner tried it and reported that they liked it; this is early driving feedback, not a combat or stealth playtest. Terrain transitions are covered headlessly; collision needs further edge-case testing as the game develops. The client currently sends input every render frame and renders the latest Worker state without interpolation. Sound suppression, stealth, shooting, combat, multiplayer movement, prediction, and pause are not implemented. Shapes and terrain colors are placeholders. No human playtest gate has been reached.

The foundation and performance reference are recorded in the [M0 report](m0.md). No balance tuning has been changed from the specification.
