# S4 — Team deathmatch experiment

## Status and play

Owner accepted this milestone for progression on November 5, 2026 (“very good. continue”). The [S5 handoff](s5.md) records the following presentation pass. The owner accepted S3 with “fine to me” and authorized the next milestone on November 5, 2026. This replaces the default Relay Control mode with one local 2v2 team deathmatch experiment, following their feedback about ring repetition and smoke camping.

Run `npm run dev` and open http://127.0.0.1:5173/. Blue is the player plus one bot; Red has two bots. Each enemy destruction gives the opposing team one kill. First to 15 team kills wins. After seven minutes the leading team wins; a tie starts up to one minute of sudden death. A lead after an entire damage tick wins overtime. Simultaneous trades remain tied, including trades at the kill target; an unresolved overtime tie is a draw. An early tied kill target starts a full overtime minute from that tick.

Five-second respawns and two-second spawn protection remain. Firing ends protection; moving through a landmark does not. The ring, rotation timer and occupancy scoring are removed from both simulation observations and presentation. Existing map sites are static search waypoints. The Relay Yard map name is retained.

## Bots and training

Bots cycle among static search areas, move to another area on arrival or timeout, approach distant visible contacts and flank nearby contacts. Low-health smoke retains its bounded retreat behavior. Historical evidence can trigger a short investigation; arriving ends it, and bounded per-bot evidence memory avoids revisiting the same stale contact. Navigation still uses terrain-aware paths, obstacle inflation and stuck recovery.

Bot decisions receive only authorized team observations and static geometry. No hidden enemy position was added to the interface. Presets still change reaction, aim uncertainty and evidence memory, with identical movement, HP, weapons and perception rules for all actors. Approved drift physics are preserved.

The last guided-training exercise now asks the player to finish a damaged enemy and earn a kill through actual projectile damage. The preceding eight exercises, range, remapping, settings and offline delivery remain available. Protocol/content versions are 5.

## TDD and verification

Tests preceded the implementation of kill scoring, protection changes, overtime and continued searching. The initial targeted run had seven expected behavioral failures: occupancy still scored, kills/trades did not score, the old win target remained, landmarks removed protection, and bots kept the same arrived-at goal. All pass after implementation. A final-lesson integration test then failed because a tap did not yet earn the required kill; the authored damaged-target fixture made the exercise completable through the shared cannon rules. A further regression failed when a bot remained in investigation after reaching its last-known contact; it now resumes search and passes.

Local verification:

- 87 unit tests pass, including simultaneous lethal trades, duplicate lethal impacts counted once, early target-tie overtime, pause/restart, perception and movement regressions.
- Strict TypeScript/production build and map validation pass.
- All 23 browser tests pass. The suite covers real Worker simulation, results/reset, settings, actual nine-exercise training, range, focus behavior and production offline restart/repair.
- The cursor layout regression initially failed under parallel browser load, then passed in isolation. Its final angle assertion now polls for the unchanged tolerance instead of assuming the renderer settles within a fixed 1.2 seconds. No aim or movement rule changed.

Headless diagnostics used an idle human, 100 seeds per preset (300 total). All terminated; Red won all of them. These are termination/navigation checks, not difficulty or fairness calibration. Maximum active shells were 5/5/6 for easy/normal/hard; longest measured live-bot stationary periods anywhere were 1.13/1.77/1.00 seconds respectively. The metric now includes all locations, unlike the prior away-from-ring metric. Death totals were 2,037 / 2,128 / 2,147.

No GitHub CI run was triggered for this experiment; local validation includes the production build and offline browser checks. Keep manual CI for a larger accepted checkpoint, following the owner's conservative CI preference.
